# ADR-0004 三模式检索架构（Hybrid + 动态超边 + rg）

## 决定

在同一检索引擎内提供三种可切换检索模式：`hybrid`（BM25 + Dense + RRF + Rerank）作为默认主路径，`hyperedge`（种子召回 + SQL 共享实体动态超边扩展 + 精排）作为跨文档多跳关联模式，`rg`（基于 `ripgrep` 的精确与正则检索）作为代码、日志与精确符号检索模式；三种模式均返回带原文定位锚点的候选证据。

## 为什么

- 纯稠密向量检索对专有名词、编号与代码标识符召回差，`hybrid` + Rerank 能以可控成本覆盖绝大多数企业文档问答。
- 离线全局 GraphRAG 建图贵且增量更新困难；借鉴 [Zleap-AI/SAG](https://github.com/Zleap-AI/SAG/blob/main/README-CN.md) 的关系表查询时动态超边思路，可在需要跨文档多跳推理时按需启用，且增量入库只需追加行记录。
- 对于代码仓库、配置项与报错堆栈，向量和词法分词都会破坏精确符号，`rg --json` 能以极低延迟返回精确 `filePath:line` 锚点。

## 代价

- 检索引擎需要维护三条召回路径及各自对应的失败处理逻辑。
- 开启 `hyperedge` 的文档在入库阶段需要额外调用 LLM 抽取 `Event` 与 `Entity`，增加入库耗时与 token 成本。
- 支持 `rg` 的信源需要在本地维护按 `source_id` 隔离的原文镜像并严格校验路径沙箱。
